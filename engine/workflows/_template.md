> **注意区分 check 与「系列内无解」。** 圆整步骤的 `on_exceed: error`
> 产生的是 `no_solution`（换设计），不是 `check_failed`，更不是 `data_missing`（补数据）。
> 三者给用户的方向完全不同，不要在文档里混为一谈。

## 采购关键词模板

<物料>采购关键词顺序：**<如 品牌 → 产品线 → 规格型号 → 物料名 → 等级 → 包装>**

| 字段 | 是否必给 | 引擎是否自动填 | 说明 |
|---|---|---|---|

> **写清楚哪些字段引擎自动填、哪些要人补**（对应 `yaml: procure.fields`）。
> 品牌通常要人补——引擎不替用户挑品牌。

再在 `knowledge/procure/keyword_templates.yaml` 的 `materials:` 下补一段同名配置
（`keyword_order` + `field_hint` + `examples`），即可用脚本一键生成链接：

```bash
python scripts/procure_link.py build -m <material> --set kind=<物料名> --set ... --format md
```

> 平台搜索 URL、关键词写法约定、防伪提示等通用规则见 `references/procurement_link.md`，
> 本文件只写该物料**特有**的关键词构成要求。
